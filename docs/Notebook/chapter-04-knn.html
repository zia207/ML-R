1. The Big Picture - What Is KNN?

The Real-World Analogy (with Simple Math)

Imagine you just moved to a new city and want to know if your new neighbourhood is safe. You ask your 5 nearest neighbours. Their answers are: [safe, safe, safe, unsafe, safe].

To decide, you simply count: - Number who say “safe”: 4 - Number who say “unsafe”: 1

Since 4 out of 5 say “safe”:

  • 4/5 = 0.8 (or 80%) say “safe”
  • You decide your neighbourhood is safe.

In KNN, the K is the number of neighbours you ask (here, K=5).

Mathematically, for each new data point: 1. Calculate the distance (e.g., Euclidean) from this point to every point in the dataset. - Example (Euclidean for 2D): distance = sqrt((x₁ - x₂)² + (y₁ - y₂)²) 2. Pick the K (e.g., 5) closest points (smallest distances). 3. For classification: Take a majority vote among these K points. - Example: If K=5 and the labels are [A, A, B, A, B], Majority is A (3 out of 5) → Predict A. 4. For regression: Compute the average value of the K points. - Example: If K=3, neighbour values are [4, 5, 6], Predicted value = (4 + 5 + 6) / 3 = 5

Key Properties

Property Explanation
Lazy learner No explicit training — it just memorises the data
Non-parametric Makes no assumption about data distribution
Instance-based Each prediction uses the raw training examples directly
Training cost Almost zero (just store data)
Prediction cost High — must compare to every training point

When to Use KNN

✅ Small-to-medium datasets (< 50,000 rows) ✅ Low-dimensional data (< 20 features) ✅ When you need a quick, interpretable baseline ✅ Recommendation systems (users similar to you liked …)

❌ Very large datasets (slow prediction) ❌ High-dimensional data (Curse of Dimensionality) ❌ When features have very different scales (must normalise!)

make_moons <- function(n_samples = 100, noise = 0.1, random_state = NULL) {
  # Makes fake 2D data that looks like two crescent moons interleaved.
  # Returns list(X=features, y=labels) with 2 classes.
  if (!is.null(random_state)) set.seed(random_state)
  n1 <- n_samples %/% 2; n2 <- n_samples - n1
  theta1 <- seq(0, pi, length.out = n1)
  theta2 <- seq(0, pi, length.out = n2)
  X1 <- cbind(cos(theta1),     sin(theta1))
  X2 <- cbind(1 - cos(theta2), 1 - sin(theta2) - 0.5)
  X  <- rbind(X1, X2)
  y  <- c(rep(0, n1), rep(1, n2))
  if (noise > 0) X <- X + matrix(rnorm(length(X), sd = noise), nrow = nrow(X))
  perm <- sample(n_samples)
  list(X = X[perm, ], y = y[perm])
}

make_classification <- function(n_samples = 100, n_features = 2, n_informative = 2,
                                 n_redundant = 0, n_repeated = 0, n_classes = 2,
                                 random_state = NULL) {
  # Make random blobs of data for classification (several classes, separated).
  # n_informative = how many features are actually "useful" (rest are just noise).
  if (!is.null(random_state)) set.seed(random_state)
  n_informative <- max(1, min(n_informative, n_features))
  centroids <- matrix(rnorm(n_classes * n_informative) * 2.0, nrow = n_classes)
  X_info_list <- list(); y_list <- integer(0)
  per_class <- n_samples %/% n_classes
  for (c in 0:(n_classes - 1)) {
    count <- if (c < n_classes - 1) per_class else n_samples - per_class * (n_classes - 1)
    Xc <- matrix(rnorm(count * n_informative), nrow = count)
    Xc <- sweep(Xc, 2, centroids[c + 1, ], "+")
    X_info_list[[c + 1]] <- Xc
    y_list <- c(y_list, rep(c, count))
  }
  X_info <- do.call(rbind, X_info_list)
  n_noise <- n_features - n_informative
  X <- if (n_noise > 0) cbind(X_info, matrix(rnorm(n_samples * n_noise), nrow = n_samples)) else X_info
  perm <- sample(n_samples)
  list(X = X[perm, , drop = FALSE], y = y_list[perm])
}

make_regression <- function(n_samples = 100, n_features = 1, noise = 0.0, random_state = NULL) {
  # Create a synthetic dataset for predicting numbers ("regression").
  if (!is.null(random_state)) set.seed(random_state)
  X <- matrix(rnorm(n_samples * n_features), nrow = n_samples)
  coef <- rnorm(n_features)
  y <- as.numeric(X %*% coef)
  if (noise > 0) y <- y + rnorm(n_samples, sd = noise)
  list(X = X, y = y)
}

train_test_split <- function(X, y, test_size = 0.2, random_state = NULL, stratify = NULL) {
  # Breaks up your data into training and testing parts. Can "stratify" so all classes
  # are equally represented in train and test.
  # Usage: split <- train_test_split(X, y); split$X_train ...
  if (!is.null(random_state)) set.seed(random_state)
  n <- if (is.matrix(X) || is.data.frame(X)) nrow(X) else length(X)

  if (!is.null(stratify)) {
    classes <- sort(unique(stratify))
    train_idx <- integer(0); test_idx <- integer(0)
    for (cls in classes) {
      cls_idx <- sample(which(stratify == cls))
      n_cls_test <- max(1, round(length(cls_idx) * test_size))
      test_idx  <- c(test_idx,  cls_idx[seq_len(n_cls_test)])
      train_idx <- c(train_idx, cls_idx[(n_cls_test + 1):length(cls_idx)])
    }
  } else {
    perm   <- sample(n)
    n_test <- max(1, round(n * test_size))
    test_idx  <- perm[seq_len(n_test)]
    train_idx <- perm[(n_test + 1):n]
  }

  idx_rows <- function(A, idx) if (is.matrix(A) || is.data.frame(A)) A[idx, , drop = FALSE] else A[idx]

  list(X_train = idx_rows(X, train_idx), X_test = idx_rows(X, test_idx),
       y_train = idx_rows(y, train_idx), y_test = idx_rows(y, test_idx))
}

cross_val_score <- function(make_estimator, X, y, cv = 5, scoring = "accuracy") {
  # Checks how good your model is via k-fold cross-validation.
  # make_estimator: a function() returning a FRESH, unfitted estimator each call
  # (this plays the role of Python's copy.deepcopy(estimator) per fold).
  X <- as.matrix(X); n <- nrow(X)
  fold_size <- n %/% cv
  scores <- numeric(cv)
  for (fold in 0:(cv - 1)) {
    start <- fold * fold_size + 1
    end   <- if (fold < cv - 1) start + fold_size - 1 else n
    mask  <- rep(FALSE, n); mask[start:end] <- TRUE
    X_tr <- X[!mask, , drop = FALSE]; X_te <- X[mask, , drop = FALSE]
    y_tr <- y[!mask]; y_te <- y[mask]
    est <- make_estimator()
    est$fit(X_tr, y_tr)
    y_pred <- est$predict(X_te)
    score <- if (scoring == "accuracy") mean(y_pred == y_te)
             else if (scoring %in% c("r2", "r2_score")) r2_score(y_te, y_pred)
             else mean(y_pred == y_te)
    scores[fold + 1] <- score
  }
  scores
}

# --- METRIC FUNCTIONS FOR EVALUATING MODELS ---

accuracy_score <- function(y_true, y_pred) mean(y_true == y_pred)

confusion_matrix <- function(y_true, y_pred) {
  # Rows: true labels. Columns: predicted labels.
  classes <- sort(unique(y_true))
  n <- length(classes)
  idx_map <- setNames(seq_len(n), as.character(classes))
  cm <- matrix(0L, n, n)
  for (i in seq_along(y_true)) {
    r <- idx_map[[as.character(y_true[i])]]; c <- idx_map[[as.character(y_pred[i])]]
    cm[r, c] <- cm[r, c] + 1L
  }
  cm
}

classification_report <- function(y_true, y_pred, target_names = NULL) {
  # precision / recall / f1-score / support for each class, plus accuracy & weighted avg.
  classes <- sort(unique(y_true))
  if (is.null(target_names)) target_names <- as.character(classes)
  cat(sprintf("%20s %10s %10s %10s %10s\n", "", "precision", "recall", "f1-score", "support"))
  cat("\n")
  total_support <- 0; w_p <- w_r <- w_f <- 0.0
  for (i in seq_along(classes)) {
    cl <- classes[i]; name <- target_names[i]
    tp <- sum(y_true == cl & y_pred == cl)
    fp <- sum(y_true != cl & y_pred == cl)
    fn <- sum(y_true == cl & y_pred != cl)
    support   <- sum(y_true == cl)
    precision <- if (tp + fp > 0) tp / (tp + fp) else 0.0
    recall    <- if (tp + fn > 0) tp / (tp + fn) else 0.0
    f1 <- if (precision + recall > 0) 2 * precision * recall / (precision + recall) else 0.0
    cat(sprintf("%20s %10.2f %10.2f %10.2f %10d\n", name, precision, recall, f1, support))
    w_p <- w_p + precision * support; w_r <- w_r + recall * support; w_f <- w_f + f1 * support
    total_support <- total_support + support
  }
  acc <- accuracy_score(y_true, y_pred)
  cat("\n")
  cat(sprintf("%20s %10s %10s %10.2f %10d\n", "accuracy", "", "", acc, total_support))
  cat(sprintf("%20s %10.2f %10.2f %10.2f %10d\n", "weighted avg",
              w_p / total_support, w_r / total_support, w_f / total_support, total_support))
}

mean_squared_error <- function(y_true, y_pred) mean((y_true - y_pred)^2)

r2_score <- function(y_true, y_pred) {
  # "R squared": 1 is perfect, 0 is same as always guessing the mean, negative is worse.
  ss_res <- sum((y_true - y_pred)^2)
  ss_tot <- sum((y_true - mean(y_true))^2)
  1.0 - ss_res / (ss_tot + 1e-10)
}

KNeighborsClassifier <- setRefClass(
  "KNeighborsClassifier",
  fields = list(n_neighbors = "numeric", metric = "character", weights = "character",
                X_train_ = "matrix", y_train_ = "ANY"),
  methods = list(
    initialize = function(n_neighbors = 5, metric = "euclidean", weights = "uniform", ...) {
      n_neighbors <<- n_neighbors; metric <<- metric; weights <<- weights
      callSuper(...)
    },
    fit = function(X, y) {
      # Just remembers all the training data (KNN is a "lazy learner": no real training)
      X_train_ <<- as.matrix(X); y_train_ <<- y
      invisible(.self)
    },
    distances_to = function(x) {
      # Distance from x to every row in training data
      diff <- sweep(X_train_, 2, x, "-")
      if (metric == "manhattan") rowSums(abs(diff)) else sqrt(rowSums(diff^2))
    },
    predict_one = function(x) {
      # Find the k closest neighbors and vote
      d <- distances_to(x)
      idx <- order(d)[seq_len(n_neighbors)]
      labs <- y_train_[idx]
      tbl <- table(labs)
      as.numeric(names(tbl)[which.max(tbl)])
    },
    predict = function(X) {
      X <- as.matrix(X)
      vapply(seq_len(nrow(X)), function(i) predict_one(X[i, ]), numeric(1))
    },
    score = function(X, y) accuracy_score(y, predict(X))
  )
)

decision_boundary_grid <- function(estimator, X, grid_resolution = 80) {
  # Computes a grid of predictions over the 2D span of X, for background shading.
  X <- as.matrix(X)
  pad <- 0.5
  gx <- seq(min(X[, 1]) - pad, max(X[, 1]) + pad, length.out = grid_resolution)

  grid <- as.matrix(expand.grid(gx, gy))
  Z <- matrix(estimator$predict(grid), nrow = length(gx))
  list(gx = gx, gy = gy, Z = Z)
}

3. Distance Metrics

To use KNN, we need a way to decide how “close” two data points are. This is done using a distance metric—a mathematical formula that calculates how far apart two points are in the feature space. The choice of distance metric determines how neighbors are found and can affect KNN’s performance and behavior.

3.1 Euclidean Distance (L2) - The “Ruler” Distance

Imagine you have two points on a piece of paper. If you use a ruler to measure the straight line from one to the other, that’s the Euclidean distance! It’s the most common way to figure out “how far apart” two things are.

Here’s the formula (don’t worry, it’s not scary):

\[d(\mathbf{a}, \mathbf{b}) = \sqrt{(a_1 - b_1)^2 + (a_2 - b_2)^2 + ... + (a_n - b_n)^2}\]

In simple terms: For each coordinate, subtract one from the other, square it (so negatives go away), add them all up, and then take the square root at the end.

It’s just the good old Pythagorean theorem — like in a right triangle, but for as many dimensions as you need!

3.2 Manhattan Distance (L1) - The City Block

Picture a city with streets in a perfect grid—think of the blocks in Manhattan, New York. To get from one place to another, you can’t walk through buildings or cut across parks; you have to walk or drive only along the streets, making turns at the corners.

Manhattan distance is just “How many blocks will you walk if you always go straight, then turn, never moving diagonally?” You add up the number of blocks up/down and left/right.

Formula: \[d(\mathbf{a}, \mathbf{b}) = \sum_{i=1}^{n} |a_i - b_i|\]

In even simpler terms: for each direction, count how far apart you are, ignore whether it’s positive or negative, and add all those distances together.

Why use it? It’s less “shocked” by one big odd value (an outlier) than Euclidean distance.

3.3 Minkowski Distance – The “Shape-Shifter” Distance

Think of Minkowski distance like a superhero distance formula that can act like both Euclidean and Manhattan distance, just by changing a setting called “p”:

\[d(\mathbf{a}, \mathbf{b}) = \left(\sum_{i=1}^{n} |a_i - b_i|^p\right)^{1/p}\]

  • If you set \(p = 1\), you get Manhattan distance (the city block kind).
  • If you set \(p = 2\), you get Euclidean distance (the straight-line with a ruler).

So, by changing “p”, you decide HOW the distance is measured!

Why should I care about feature scaling? Imagine you’re measuring height (in meters, so just 0–2) and bank balance (in dollars, could be 0–100,000!). Without fixing this, the bank balance will “shout” so loud that height doesn’t matter at all in the calculation. Always put your features on the same scale before running KNN – otherwise one big number will drown out the rest!

# ── Three distance functions, explained ─────────────────────────────────────

euclidean_distance <- function(a, b) {
  # Straight-line (ruler) distance between two points.
  # Step 1: subtract each coordinate pair. Step 2: square. Step 3: sum. Step 4: sqrt.
  sqrt(sum((a - b)^2))
}

manhattan_distance <- function(a, b) {
  # City-block distance — sum of absolute differences.
  sum(abs(a - b))
}

minkowski_distance <- function(a, b, p = 2) {
  # General Minkowski distance. p=1 -> Manhattan, p=2 -> Euclidean.
  sum(abs(a - b)^p)^(1 / p)
}

5. KNN From-Scratch

Building KNN from scratch helps you understand exactly what happens under the hood. Every line below is annotated so a complete beginner can follow along.

The Algorithm in Plain English

For each new test point:
    1. Calculate the distance to EVERY training point
    2. Sort those distances from smallest to largest
    3. Keep only the first K entries (K nearest neighbours)
    4. For classification: take a majority vote of their labels
       For regression:     take the average of their values
Code 
# ────────────────────────────────────────────────────────────────────────────
#  KNN CLASSIFIER — from scratch, line-by-line explanation
# ────────────────────────────────────────────────────────────────────────────

KNNClassifierScratch <- setRefClass(
  "KNNClassifierScratch",
  fields = list(k = "numeric", metric = "character", X_train = "ANY", y_train = "ANY"),
  methods = list(
    initialize = function(k = 3, metric = "euclidean", ...) {
      # Store hyperparameters — these are set BEFORE training
      k <<- k; metric <<- metric
      X_train <<- NULL; y_train <<- NULL   # placeholders — filled during fit()
      callSuper(...)
    },

    fit = function(X, y) {
      # 'Training' step — KNN is a LAZY learner, so fit() just stores data.
      X_train <<- X   # memorise features
      y_train <<- y   # memorise labels
      invisible(.self)   # allow chaining: clf$fit(X, y)$predict(X_test)
    },

    compute_distance = function(a, b) {
      # Compute the distance between two points a and b.
      if (metric == "euclidean") {
        sqrt(sum((a - b)^2))       # sqrt(sum (ai - bi)^2)
      } else if (metric == "manhattan") {
        sum(abs(a - b))            # sum |ai - bi|
      } else {
        stop(sprintf("Unknown metric '%s'. Use 'euclidean' or 'manhattan'.", metric))
      }
    },

    predict_single = function(x) {
      # Predict the class label for ONE query point x. This is the core KNN logic.
      # STEP 1: distance from x to every training point
      dists <- vapply(seq_len(nrow(X_train)), function(i) compute_distance(x, X_train[i, ]), numeric(1))
      # STEP 2: sort by distance (closest first) & STEP 3: keep only the K nearest
      k_nearest <- order(dists)[seq_len(k)]
      # STEP 4: labels of those K neighbours
      k_labels <- y_train[k_nearest]
      # STEP 5: majority vote — the most common label wins
      tbl <- table(k_labels)
      as.numeric(names(tbl)[which.max(tbl)])
    },

    predict = function(X) {
      # Predict labels for a matrix of query points.
      vapply(seq_len(nrow(X)), function(i) predict_single(X[i, ]), numeric(1))
    },

    accuracy = function(X, y_true) {
      # Convenience: predict and compute accuracy in one call.
      y_pred <- predict(X)
      mean(y_pred == y_true)
    }
  )
)

# ── KNN REGRESSOR — from scratch ─────────────────────────────────────────────
# For REGRESSION (predicting a continuous number) the only difference
# from the classifier is STEP 5:
#   - Classifier -> majority VOTE  (pick the most common label)
#   - Regressor  -> AVERAGE        (take the mean of K neighbours' values)

KNNRegressorScratch <- setRefClass(
  "KNNRegressorScratch",
  fields = list(k = "numeric", X_train = "ANY", y_train = "ANY"),
  methods = list(
    initialize = function(k = 3, ...) {
      k <<- k; X_train <<- NULL; y_train <<- NULL
      callSuper(...)
    },
    fit = function(X, y) { X_train <<- X; y_train <<- y; invisible(.self) },
    predict_single = function(x) {
      # Compute distance to every training point, nearest first, average their K targets
      dists <- vapply(seq_len(nrow(X_train)), function(i) sqrt(sum((x - X_train[i, ])^2)), numeric(1))
      k_nearest <- order(dists)[seq_len(k)]
      mean(y_train[k_nearest])   # return their AVERAGE (not a vote!)
    },
    predict = function(X) vapply(seq_len(nrow(X)), function(i) predict_single(X[i, ]), numeric(1))
  )
)

8. How K Affects the Model

K is the most important hyperparameter in KNN. It controls the bias-variance tradeoff:

K value Boundary Bias Variance Risk
Small K (e.g. K=1) Very jagged, irregular Low High Overfitting
Medium K Smoother Medium Medium Best sweet spot
Large K (e.g. K=n) Very smooth, almost flat High Low Underfitting

K=1: Model perfectly memorises training data — predicts training labels with 100% accuracy, but fails on new data. K=n (n = number of training samples): Predicts the same class for everything — the majority class.

9. Choosing the Best K with Cross-Validation

What Is Cross-Validation?

Instead of evaluating on a single train/test split (which can be lucky or unlucky), k-fold cross-validation splits the training data into k equally-sized folds. For each fold: - Use that fold as a mini-test set - Train on the remaining folds - Record accuracy

Finally, average the k accuracy scores. This gives a much more reliable estimate of model performance.

⚠️ Note: The “k” in k-fold cross-validation is different from the “K” in KNN!

Code 
# ── Find the best K using 5-fold cross-validation ────────────────────────────

X_full <- iris_data$data
y_full <- iris_data$target

scaler_full <- StandardScaler$new()
X_full_sc <- scaler_full$fit_transform(X_full)

k_range  <- 1:30   # test K from 1 to 30
cv_means <- numeric(length(k_range))
cv_stds  <- numeric(length(k_range))

set.seed(SEED)
for (i in seq_along(k_range)) {
  k <- k_range[i]
  # cross_val_score runs 5-fold CV and returns 5 accuracy scores
  scores <- cross_val_score(function() KNeighborsClassifier$new(n_neighbors = k),
                             X_full_sc, y_full, cv = 5, scoring = "accuracy")
  cv_means[i] <- mean(scores)
  cv_stds[i]  <- popsd(scores)

11. K-Means Clustering - Unsupervised Grouping

KNN vs K-Means — What Is the Difference?

Both algorithms have a K and both use distances, but they solve completely different problems:

Feature KNN (K-Nearest Neighbors) K-Means Clustering
Learning type Supervised (needs labels) Unsupervised (no labels needed)
Goal Classify new points / predict values Discover hidden groups in data
K refers to Number of neighbours to consult Number of clusters to form
Training Lazy — just stores all data Iterative centroid update
Output Class label or numeric value Cluster assignment (0, 1, 2, …)
Distance used for Finding the K closest training points Assigning each point to its nearest centroid

Simple rule: if you have labels → use KNN (supervised). If you have no labels → use K-Means (unsupervised).

11.1 The Real-World Analogy

Imagine a teacher receives 200 student essays but has no marking rubric and no grades yet. She reads through them and naturally groups similar essays together: - Group A: short, poorly structured, many grammar errors - Group B: medium length, decent structure - Group C: long, well-argued, near-perfect grammar

She did K-Means clustering with K=3 — found 3 natural groups with no predefined labels!

11.2 The Algorithm Step-by-Step

INITIALISE: Randomly place K centroid points anywhere in the data space

REPEAT until centroids stop moving:
    STEP 1 — ASSIGN: For every data point, compute its distance to each centroid.
                     Assign the point to the NEAREST centroid.
    STEP 2 — UPDATE: For each cluster, move its centroid to the MEAN
                     (average) position of all points assigned to it.

STOP when centroid movement < tolerance (convergence)

11.3 Key Vocabulary

Term Plain English
Centroid The “center” of a cluster — the average position of all its member points
Cluster A group of data points that are closer to each other than to other groups
Inertia Total squared distance of every point to its nearest centroid — lower = tighter clusters
Convergence When centroids barely move between iterations (algorithm has found a stable solution)
Elbow method Plot inertia vs K values — look for the “knee” where adding more clusters stops helping much

11.4 When to Use K-Means

✅ Customer segmentation (group customers by purchasing behaviour) ✅ Image compression (group similar pixel colours) ✅ Document clustering (group similar articles) ✅ Anomaly detection (points far from all centroids are outliers)

❌ When clusters have very different sizes ❌ When clusters are non-spherical / ring-shaped ❌ When you don’t know a good K upfront (use elbow method to find it!)

Code 
# ── K-Means Clustering — from scratch, every line explained ──────────────────
# Just like KNNClassifierScratch, this class uses ONLY base R.
# Every step is annotated so a beginner can follow along.

KMeans <- setRefClass(
  "KMeans",
  fields = list(n_clusters = "numeric", max_iter = "numeric", random_state = "ANY", tol = "numeric",
                cluster_centers_ = "matrix", labels_ = "numeric", inertia_history_ = "numeric",
                inertia_ = "numeric", n_iter_ = "numeric"),
  methods = list(
    initialize = function(n_clusters = 3, max_iter = 300, random_state = NULL, tol = 1e-4, ...) {
      n_clusters <<- n_clusters; max_iter <<- max_iter; random_state <<- random_state; tol <<- tol
      cluster_centers_ <<- matrix(numeric(0), 0, 0)
      labels_ <<- numeric(0); inertia_history_ <<- numeric(0)
      inertia_ <<- NA_real_; n_iter_ <<- 0
      callSuper(...)
    },

    assign_labels = function(X) {
      # For each data point in X, find the index of the nearest centroid (0-indexed).
      K <- nrow(cluster_centers_)
      dists <- vapply(seq_len(K), function(k) {
        sqrt(rowSums(sweep(X, 2, cluster_centers_[k, ], "-")^2))
      }, numeric(nrow(X)))   # shape: (n_samples, K), always a matrix even if K==1
      apply(dists, 1, which.min) - 1L
    },

    compute_inertia = function(X, labels, centers) {
      # Inertia = sum of squared distances from each point to its cluster centroid.
      total <- 0.0
      for (k in 0:(n_clusters - 1)) {
        mask <- labels == k
        if (any(mask)) {
          diff <- sweep(X[mask, , drop = FALSE], 2, centers[k + 1, ], "-")
          total <- total + sum(diff^2)
        }
      }
      total
    },

    fit = function(X) {
      # Find K clusters in the dataset X. NO LABELS needed — this is unsupervised!
      X <- as.matrix(X)
      if (!is.null(random_state)) set.seed(random_state)

      # INITIALISATION: randomly pick K existing data points as starting centroids
      idx <- sample(seq_len(nrow(X)), n_clusters, replace = FALSE)
      cluster_centers_ <<- X[idx, , drop = FALSE]

      labels_ <<- rep(0L, nrow(X))
      inertia_history_ <<- numeric(0)

      iteration <- 0
      for (it in seq_len(max_iter)) {
        iteration <- it

        # STEP 1: ASSIGN — find nearest centroid for every point
        new_labels <- assign_labels(X)

        # STEP 2: UPDATE — move each centroid to its cluster's mean
        new_centers <- do.call(rbind, lapply(0:(n_clusters - 1), function(k) {
          if (any(new_labels == k)) colMeans(X[new_labels == k, , drop = FALSE])
          else cluster_centers_[k + 1, ]   # keep old centroid if cluster is empty
        }))

        inertia <- compute_inertia(X, new_labels, new_centers)
        inertia_history_ <<- c(inertia_history_, inertia)

        # CONVERGENCE CHECK: did centroids move much?
        shift <- sqrt(sum((new_centers - cluster_centers_)^2))

        cluster_centers_ <<- new_centers
        labels_ <<- new_labels

        if (shift < tol) break   # centroids barely moved — stable solution!
      }

      inertia_ <<- inertia_history_[length(inertia_history_)]
      n_iter_  <<- iteration
      invisible(.self)
    },

    predict = function(X) {
      # Assign NEW (unseen) data points to the nearest existing centroid.
      assign_labels(as.matrix(X))
    },

    fit_predict = function(X) { fit(X); labels_ }
  )
)

12. The Curse of Dimensionality

The Problem

KNN relies on the idea that nearby points are similar. But in high-dimensional spaces, this idea breaks down.

Intuition

Imagine you want to cover 10% of a line segment (1D): you need a segment of length 0.1. To cover 10% of a square (2D): you need a side of length √0.1 ≈ 0.32. To cover 10% of a cube (3D): you need a side of √∛0.1 ≈ 0.46. In 10 dimensions (10D): you need a side of 0.1^(1/10) ≈ 0.79 — almost the entire space!

\[\text{Side length to cover fraction } f \text{ in } d \text{ dimensions} = f^{1/d}\]

Consequence: In high dimensions, the K nearest neighbours are no longer actually “near”. All pairwise distances become approximately equal, making KNN meaningless.

Solutions

  • Dimensionality reduction: PCA, t-SNE, UMAP before applying KNN
  • Feature selection: remove irrelevant features
  • Switch to a different model: tree-based models, SVMs, neural nets handle high-d better

                              random_state = SEED)
  X_cod <- cod$X; y_cod <- cod$y
  split_cod <- train_test_split(X_cod, y_cod, test_size = 0.3, random_state = SEED)
  X_c_tr <- split_cod$X_train; X_c_te <- split_cod$X_test
  y_c_tr <- split_cod$y_train; y_c_te <- split_cod$y_test

  sc_c <- StandardScaler$new()
  X_c_tr_sc <- sc_c$fit_transform(X_c_tr)
  X_c_te_sc <- sc_c$transform(X_c_te)

  knn_c <- KNeighborsClassifier$new(n_neighbors = 5)
  knn_c$fit(X_c_tr_sc, y_c_tr)
  knn_accs[i] <- knn_c$score(X_c_te_sc, y_c_te)

Concept What You Learned
KNN Intuition Ask K nearest neighbours, take majority vote (classify) or average (regress)
Distance Metrics Euclidean (L2), Manhattan (L1), Minkowski — always scale features first!
Lazy Learner No real training — stores all data, does all computation at prediction time
Classification Returns the most common class label among K neighbours
Regression Returns the mean target value among K neighbours
K hyperparameter Small K = high variance (overfit) · Large K = high bias (underfit)
Cross-validation Reliable, data-driven way to find the best K without touching the test set
Feature scaling Mandatory — without scaling, large-range features dominate distances
Curse of Dimensionality KNN degrades above ~20 features — all distances become similar, “near” loses meaning

Chapter Summary — K-Means Clustering

Concept What You Learned
K-Means Intuition Iteratively assign points to K centroids and re-centre until convergence
Unsupervised Requires no labels — discovers natural groups in raw data
Centroid The mean (average) position of all points in a cluster
Inertia Within-cluster sum of squared distances — lower = tighter clusters
Elbow Method Plot inertia vs K; pick the K at the “elbow” where gains flatten
Convergence Centroids stop moving when assignments no longer change

KNN vs K-Means — Quick Reference

KNN K-Means
Type Supervised Unsupervised
Labels needed? Yes No
K means Number of neighbours Number of clusters
Distance used for Finding nearest training points Assigning to nearest centroid
Output Class label / numeric value Cluster index (0, 1, 2, …)

Complexity

Algorithm Operation Time Complexity
KNN Training \(O(1)\) — just store data
KNN Prediction (brute force) \(O(n \cdot p)\) per query
KNN Prediction (KD-tree) \(O(p \cdot \log n)\) per query
K-Means Fit (per iteration) \(O(n \cdot K \cdot p)\)

where \(n\) = training samples, \(p\) = features, \(K\) = number of neighbours / clusters.
