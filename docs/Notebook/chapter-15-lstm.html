Part A: LSTM Theory

15.1 Overview

An LSTM is a smarter kind of RNN, built to fix the forgetfulness problem I mentioned. “LSTM” stands for Long Short-Term Memory, and the name is the whole idea: it can hold onto important information for a long time instead of letting it fade after a few steps.

Here’s the intuition. A plain RNN has one memory that gets completely overwritten at every step — so old information washes out fast. An LSTM adds a second, protected memory line (called the cell state) that runs straight through, like a conveyor belt. Information can ride along that belt untouched for many steps. The clever part is a set of gates — little valves that decide what gets added to the belt, what gets wiped off it, and what gets read out of it.

Think of it like keeping notes while reading a long book. The conveyor belt is your notebook. At each page you make three small decisions: cross out notes that no longer matter, jot down new important facts, and glance at the relevant notes to answer whatever you’re thinking about right now. Those three decisions are the three gates.

A Recurrent Neural Network (Chapter 14) reads a sequence one step at a time and keeps a single “memory” vector \(\mathbf{h}_t\) that it rewrites at every step:

\[\mathbf{h}_t = \tanh(\mathbf{W}\,[\mathbf{h}_{t-1}, \mathbf{x}_t] + \mathbf{b})\]

The dummy version: imagine whispering a message down a long line of people. Each person re‑says it in their own words (\(\tanh\) squashes it a little every time). After 50 people the original message is mush. That “re‑squashing at every step” is mathematically the vanishing‑gradient problem — when the network learns, the correction signal has to travel backwards through all those \(\tanh\) squashes and gets multiplied down to almost zero. So an RNN simply cannot learn long‑range dependencies.

15.2 The LSTM fix: add a memory highway

The LSTM (Hochreiter & Schmidhuber, 1997) keeps the ordinary hidden state \(\mathbf{h}_t\) and adds a second line, the cell state \(\mathbf{C}_t\). Think of \(\mathbf{C}_t\) as a conveyor belt running straight across the top of the network. Information can ride the belt for hundreds of steps almost untouched — the only things allowed to change it are simple, learnable valves called gates.

There are three gates, each a little neural layer that outputs numbers between 0 and 1 (a \(\sigma\) / sigmoid), acting like a dimmer switch:

Gate Symbol Dummy meaning “0 means…” “1 means…”
Forget \(\mathbf{f}_t\) how much old memory to keep erase it keep all of it
Input \(\mathbf{i}_t\) how much new info to write write nothing write it all
Output \(\mathbf{o}_t\) how much memory to reveal now stay silent speak fully

Because the belt is updated by addition (not repeated multiplication/squashing), the learning signal can flow back across many steps without vanishing. That single design choice is the whole magic.

15.3 The math, one gate at a time

At each step \(t\) the cell receives the new input \(\mathbf{x}_t\), the previous hidden state \(\mathbf{h}_{t-1}\), and the previous belt value \(\mathbf{C}_{t-1}\). It glues \(\mathbf{x}_t\) and \(\mathbf{h}_{t-1}\) together (written \([\mathbf{h}_{t-1}, \mathbf{x}_t]\)) and computes:

\[\mathbf{f}_t = \sigma(\mathbf{W}_f\,[\mathbf{h}_{t-1}, \mathbf{x}_t] + \mathbf{b}_f) \qquad \textbf{Forget gate}\] > “Looking at the new input and my last thought, what fraction of each memory slot should I keep?” Output is between 0 (drop) and 1 (keep).

\[\mathbf{i}_t = \sigma(\mathbf{W}_i\,[\mathbf{h}_{t-1}, \mathbf{x}_t] + \mathbf{b}_i) \qquad \textbf{Input gate}\] > “How much am I allowed to write into each memory slot right now?”

\[\tilde{\mathbf{g}}_t = \tanh(\mathbf{W}_g\,[\mathbf{h}_{t-1}, \mathbf{x}_t] + \mathbf{b}_g) \qquad \textbf{Candidate}\] > “Here is the actual new content I’m proposing to write” (range \(-1\) to \(1\)).

\[\mathbf{C}_t = \mathbf{f}_t \odot \mathbf{C}_{t-1} + \mathbf{i}_t \odot \tilde{\mathbf{g}}_t \qquad \textbf{Update the belt}\] > The key line. Keep a fraction \(\mathbf{f}_t\) of the old belt, then add a fraction \(\mathbf{i}_t\) of the new content. Notice it is an addition — that is why gradients don’t vanish.

\[\mathbf{o}_t = \sigma(\mathbf{W}_o\,[\mathbf{h}_{t-1}, \mathbf{x}_t] + \mathbf{b}_o) \qquad \textbf{Output gate}\] > “How much of the belt should I reveal as my answer this step?”

\[\mathbf{h}_t = \mathbf{o}_t \odot \tanh(\mathbf{C}_t) \qquad \textbf{Hidden state}\] > Squash the belt to \([-1,1]\) and let the output gate decide how much of it leaves the cell.

Symbols: \(\sigma\) = sigmoid (0→1 dimmer), \(\tanh\) = squash to \([-1,1]\), \(\odot\) = element‑wise multiply, \([\cdot,\cdot]\) = concatenate.

Trace the flow. The green belt \(C_{t-1}\) enters top‑left, gets multiplied by the forget gate (×), then has the new content added (+) to become \(C_t\). New content is the input gate times the candidate (\(i \odot \tilde g\)). To produce the answer \(h_t\), the belt is squashed by \(\tanh\) and multiplied by the output gate. The dotted lines show that all four gates see the same input bus \([\mathbf{h}_{t-1}, \mathbf{x}_t]\).

15.4 How many parameters?

For hidden size \(H\) and input size \(D\) each gate has a weight matrix of shape \((H,\,H+D)\) plus a bias of size \(H\). There are 4 gates, so:

\[\#\text{params} = 4\,\big[H(H+D) + H\big] = 4H(H+D+1)\]

A GRU has 3 such blocks instead of 4, and a Stacked/Bidirectional model multiplies this by the number of layers/directions. We will print exact counts from our own parameter arrays later.

15.5 The variants

(a) Peephole connections

Let the gates also peek at the belt \(\mathbf{C}_{t-1}\) itself, not just \(\mathbf{h}_{t-1}\): \[\mathbf{f}_t = \sigma(\mathbf{W}_f\,[\mathbf{C}_{t-1}, \mathbf{h}_{t-1}, \mathbf{x}_t] + \mathbf{b}_f)\] > the dimmer switches get to look at the conveyor belt directly. Helps with precise timing tasks.

(b) GRU — Gated Recurrent Unit (the lightweight cousin)

Merges the cell and hidden state and uses only two gates: update \(z\) and reset \(r\). \[\mathbf{z}_t = \sigma(\mathbf{W}_z[\mathbf{h}_{t-1},\mathbf{x}_t]),\quad \mathbf{r}_t = \sigma(\mathbf{W}_r[\mathbf{h}_{t-1},\mathbf{x}_t])\] \[\tilde{\mathbf{h}}_t = \tanh(\mathbf{W}[\mathbf{r}_t\odot\mathbf{h}_{t-1},\mathbf{x}_t]),\quad \mathbf{h}_t = (1-\mathbf{z}_t)\odot\mathbf{h}_{t-1} + \mathbf{z}_t\odot\tilde{\mathbf{h}}_t\] > one knob (\(z\)) blends old vs new memory; another (\(r\)) decides how much old memory to use when proposing new content. Fewer parameters, faster, often just as good.

(c) Bidirectional LSTM (BiLSTM)

Run one LSTM forward and another backward, then glue their hidden states together. \[\mathbf{h}_t = [\,\overrightarrow{\mathbf{h}}_t,\ \overleftarrow{\mathbf{h}}_t\,]\] > read the sentence left‑to‑right and right‑to‑left so each word is understood with full context. Great for classification/tagging where the whole sequence is known — but not for real‑time forecasting (you can’t see the future).

(d) Stacked (deep) LSTM

Feed the hidden‑state sequence of layer 1 as the input to layer 2, and so on. > layer 1 learns simple patterns, layer 2 learns patterns‑of‑patterns. More power, more compute, needs more data.

(e) Encoder–Decoder (seq2seq)

One LSTM encodes the input sequence into a context vector; a second LSTM decodes it into an output sequence. > the encoder “reads and summarises”, the decoder “writes”. This is the backbone of classic machine translation and multi‑step forecasting.

Part B: An LSTM from scratch in R (that actually trains)

Frameworks hide the mechanics. Here we implement the forward pass and back‑propagation‑through‑time (BPTT) using nothing but base R, and train it with Adam to forecast the next value of a noisy sine wave. # Let's build an LSTM (Long Short-Term Memory) neural network from scratch
# using simple base-R math. It's meant to predict a number from a sequence of numbers,
# learning "memory" over time. We'll skip the jargon and explain it as we go!

sigmoid <- function(x) {
  # squashes input to between 0 and 1 (like a smooth switch)
  1.0 / (1.0 + exp(-x))
}

# A generic Adam optimiser step, shared by ScratchLSTM and ScratchGRU below (mirrors the
# Python source's `step = ScratchLSTM.step` trick of reusing one implementation for both).
adam_step <- function(obj, grads, lr = 0.01, b1 = 0.9, b2 = 0.999, eps = 1e-8) {
  obj$t <- obj$t + 1
  for (p in obj$params) {
    g <- grads[[p]]
    obj$m[[p]] <- b1 * obj$m[[p]] + (1 - b1) * g          # running average for momentum
    obj$v[[p]] <- b2 * obj$v[[p]] + (1 - b2) * (g * g)    # running average for squared grads
    mhat <- obj$m[[p]] / (1 - b1^obj$t)                   # bias correction for momentum
    vhat <- obj$v[[p]] / (1 - b2^obj$t)                   # bias correction for squared grads
    newval <- obj$field(p) - lr * mhat / (sqrt(vhat) + eps)  # the update!
    obj$field(p, newval)
  }
}

# An LSTM (Long Short-Term Memory) model made with just base R, with every step spelled out.
# This network learns to look at sequences of numbers and predict the next number.
#
# How does it work? Think of LSTM as a repeating loop with:
#   - Gates (like switches) that decide what to remember and what to forget
#   - A "belt" (cell state) that carries memory forward in time
ScratchLSTM <- setRefClass(
  "ScratchLSTM",
  fields = list(W = "matrix", b = "numeric", Wy = "matrix", by = "numeric",
                H = "numeric", D = "numeric", params = "character",
                m = "list", v = "list", t = "numeric"),
  methods = list(
    initialize = function(input_size = 1, hidden_size = 1, seed = 42, ...) {
      set.seed(seed)
      D <<- input_size; H <<- hidden_size
      k <- 1.0 / sqrt(H)  # initialize weights small so learning is stable

      # All the gates (input, forget, cell update, output) use the same big weight matrix!
      W <<- matrix(runif(4 * H * (D + H), -k, k), nrow = 4 * H, ncol = D + H)
      bvec <- rep(0.0, 4 * H)
      bvec[(H + 1):(2 * H)] <- 1.0    # set forget gate bias to 1, helps remembering at first
      b <<- bvec

      Wy <<- matrix(runif(H, -k, k), nrow = 1, ncol = H)  # converts hidden to output
      by <<- 0.0

      params <<- c("W", "b", "Wy", "by")
      init_adam()   # preps memory for the Adam optimizer (a fancy way to update weights)
      callSuper(...)
    },
    init_adam = function() {
      # This sets up parameters for the Adam optimizer (basically: momentum and caching for
      # smoother learning)
      m <<- setNames(lapply(params, function(p) { z <- field(p); z[] <- 0; z }), params)
      v <<- setNames(lapply(params, function(p) { z <- field(p); z[] <- 0; z }), params)
      t <<- 0
    },
    forward = function(x) {
      # Think of this as sending the input sequence through the LSTM, step by step.
      # x: matrix (T, D) -- a sequence with T steps, each with D numbers.
      # Returns the prediction and a "cache" of everything we did, so we can work backwards later.
      h <- rep(0.0, H)  # hidden state (the memory that gets revealed at each step)
      cc <- rep(0.0, H) # cell state, the "belt" that carries long-term memory
      Tn <- nrow(x)
      cache <- vector("list", Tn)
      for (tt in 1:Tn) {
        z <- c(h, x[tt, ])            # join hidden memory and input
        a <- as.numeric(W %*% z) + b  # math: compute pre-activations for all 4 gates

        # Now split up these activations:
        i <- sigmoid(a[1:H])              # input gate: should we remember this new info?
        f <- sigmoid(a[(H + 1):(2 * H)])  # forget gate: should we forget what we remembered so far?
        g <- tanh(a[(2 * H + 1):(3 * H)]) # cell update: new info to add (with input gate's permission)
        o <- sigmoid(a[(3 * H + 1):(4 * H)])  # output gate: how much of the memory belt to reveal

        # Update memory belt: forget old stuff and add new stuff (with the switches' permission)
        cc <- f * cc + i * g

        # Output: take memory belt, squash it, and filter by output switch
        tc <- tanh(cc)
        h <- o * tc

        # Store everything: needed for learning updates
        cache[[tt]] <- list(z = z, i = i, f = f, g = g, o = o, c = cc, tc = tc, h = h)
      }

      # At the end, make a prediction using the last hidden state
      yhat <- as.numeric(Wy %*% h + by)
      list(yhat = yhat, cache = cache, x = x)
    },
    backward = function(pack, dy) {
      # Work backwards through all steps! This computes how to tweak weights for better predictions.
      # pack: everything we remembered in forward()
      # dy: how much changing the output changes the loss (for MSE, it's 2*error)
      # Returns: list of gradients, one for each parameter
      cache <- pack$cache; x <- pack$x
      Tn <- length(cache)
      dW <- matrix(0, nrow = nrow(W), ncol = ncol(W))
      db <- rep(0.0, length(b))
      dWy <- matrix(0, nrow = nrow(Wy), ncol = ncol(Wy))
      dby <- 0.0

      # Output layer's gradients (easy)
      hT <- cache[[Tn]]$h
      dWy <- dWy + dy * matrix(hT, nrow = 1)
      dby <- dby + dy

      dh_next <- as.numeric(base::t(Wy) * dy)  # how changing hidden state changes output
      dc_next <- rep(0.0, H)                   # how changing cell state changes output

      # Go backward, step by step, through the sequence
      for (tt in Tn:1) {
        ci <- cache[[tt]]
        c_prev <- if (tt > 1) cache[[tt - 1]]$c else rep(0.0, H)

        dh <- dh_next                                  # gradient from the future
        do_ <- dh * ci$tc                               # output gate's part
        dc <- dh * ci$o * (1 - ci$tc^2) + dc_next        # flow through tanh, accumulate future grads
        di <- dc * ci$g                                 # input gate's part
        dg <- dc * ci$i                                 # cell update's part
        df <- dc * c_prev                               # forget gate's part
        dc_prev <- dc * ci$f                             # carry the belt gradient backwards

        # Now: How do you tweak activations to get those effects?
        dai <- di * ci$i * (1 - ci$i)
        daf <- df * ci$f * (1 - ci$f)
        dag <- dg * (1 - ci$g^2)
        dao <- do_ * ci$o * (1 - ci$o)
        da <- c(dai, daf, dag, dao)

        # Regular base-R math for the gradients
        dW <- dW + outer(da, ci$z)
        db <- db + da
        dz <- as.numeric(base::t(W) %*% da)
        dh_next <- dz[1:H]
        dc_next <- dc_prev
      }

      # Clamp gradients to keep learning stable (avoid huge numbers!)
      dW <- pmin(pmax(dW, -5), 5)
      db <- pmin(pmax(db, -5), 5)
      dWy <- pmin(pmax(dWy, -5), 5)
      dby <- pmin(pmax(dby, -5), 5)
      list(W = dW, b = db, Wy = dWy, by = dby)
    },
    step = function(grads, lr = 0.01, b1 = 0.9, b2 = 0.999, eps = 1e-8) {
      # Actually update weights, using the Adam optimizer -- a smart way of adjusting the step size.
      adam_step(.self, grads, lr, b1, b2, eps)
    }
  )
)

# --- "Explain for dummies": Training the Scratch LSTM on a wiggly (noisy) sine wave ---

# 1. Make a wiggly sine wave with noise, like a drunk snake!
set.seed(0)  # always get the same random numbers each run
Tn_b <- 200  # how long is our snake?
series_b <- sin((0:(Tn_b - 1)) * 0.2) + 0.1 * rnorm(Tn_b)  # sine shape, plus random noise

LOOK <- 12  # how much "history" will we use to guess the next value?

# 2. Chop the snake into overlapping windows for the LSTM to look at
X_b <- matrix(0, nrow = Tn_b - LOOK, ncol = LOOK)  # shape: (num_examples, LOOK); 1 feature per step
for (i in 0:(Tn_b - LOOK - 1)) X_b[i + 1, ] <- series_b[(i + 1):(i + LOOK)]
y_b <- series_b[(LOOK + 1):Tn_b]  # the real "next" value after each window

N_TRAIN <- 150  # how many will we train on?

# 3. Build our hand-made LSTM!
model_b <- ScratchLSTM$new(input_size = 1, hidden_size = 16, seed = 1)

history_b <- c()
for (epoch in 1:30) {  # do 30 rounds (epochs) through our data
  # Shuffle the order (for fun and to help learning)
  order_ <- sample(N_TRAIN)
  sq_err <- 0.0  # will keep track of squared errors

  for (j in order_) {  # go through each window
    xj <- matrix(X_b[j, ], ncol = 1)   # reshape this window to (LOOK, 1) for forward()
    res <- model_b$forward(xj)         # guess the next value!
    err <- res$yhat - y_b[j]           # how far off was the guess?
    sq_err <- sq_err + err^2           # add up the squared error
    # Update the LSTM to make it less wrong next time (MSE loss gradient is 2*err)
    model_b$step(model_b$backward(list(cache = res$cache, x = res$x), 2 * err), lr = 0.01)
  }
  # How well did we do this round (on average)?
  history_b <- c(history_b, sq_err / N_TRAIN)
  if (epoch %% 5 == 0) cat(sprintf("epoch %2d   train MSE = %.4f\n", epoch, history_b[length(history_b)]))
}

# 4. Did our LSTM learn the drunk snake?
# Let's see how it does on fresh data it didn't get to see ("held-out tail")
preds_b <- sapply((N_TRAIN + 1):length(y_b), function(j) {
  xj <- matrix(X_b[j, ], ncol = 1)
  model_b$forward(xj)$yhat
})
actual_b <- y_b[(N_TRAIN + 1):length(y_b)]
rmse_b <- sqrt(mean((preds_b - actual_b)^2))
cat(sprintf("\nHeld-out RMSE = %.4f  (noise std was 0.10)\n", rmse_b))

Part C: The full pipeline from scratch (simulated data)

No torch, no keras — we reuse the ScratchLSTM engine from Part B and add a small GRU built the same way, then run the complete train → validate → test → forecast workflow in pure R.

The four ingredients of any sequence-forecasting job

  1. Windowing — turn one long series into many (lookback → next value) examples.
  2. Chronological split — train on the past, validate on the middle, test on the most recent slice. Never shuffle time.
  3. Scaling fit on the training part only — so the model never “sees” test statistics.
  4. A training loop with validation-based early stopping.

First we add a ScratchGRU (its gates and back-prop derived by hand, like the LSTM) plus a tiny R toolkit: a min-max scaler, a training harness, and metrics.

# This class is a super basic version of a GRU neural network — a type of machine learning model
# that works well with time series or sequences (like songs, weather, or stock prices).
# It's written entirely from scratch using only base R, so you learn how it works under the hood.

# A basic GRU (Gated Recurrent Unit) for regression tasks made in base R.
# Just like ScratchLSTM, but even simpler. Three key methods:
#   - forward(x): Runs a prediction through the mini brain, returns output and details for training.
#   - backward(cache, dy): Figures out how wrong the prediction was and how to nudge the weights to fix it.
#   - step(grads): Actually changes the "brain" weights using Adam optimizer math.
ScratchGRU <- setRefClass(
  "ScratchGRU",
  fields = list(Wz = "matrix", Wr = "matrix", Wh = "matrix", bz = "numeric", br = "numeric", bh = "numeric",
                Wy = "matrix", by = "numeric", H = "numeric", D = "numeric", params = "character",
                m = "list", v = "list", t = "numeric"),
  methods = list(
    initialize = function(input_size = 1, hidden_size = 1, seed = 42, ...) {
      # input_size: How many numbers come in at once (e.g., features per timestep)
      # hidden_size: How big is the hidden memory chunk? (bigger = more capacity)
      set.seed(seed)
      D <<- input_size; H <<- hidden_size
      k <- 1 / sqrt(H)
      Z <- D + H  # The total size once we stick input and memory together
      # Each "gate" and output gets its own weight grid ("W...") and bias ("b...")
      Wz <<- matrix(runif(H * Z, -k, k), nrow = H, ncol = Z)  # "Update" gate weights
      Wr <<- matrix(runif(H * Z, -k, k), nrow = H, ncol = Z)  # "Reset" gate weights
      Wh <<- matrix(runif(H * Z, -k, k), nrow = H, ncol = Z)  # For the candidate new memory
      bz <<- rep(0.0, H); br <<- rep(0.0, H); bh <<- rep(0.0, H)
      Wy <<- matrix(runif(H, -k, k), nrow = 1, ncol = H)      # Final output weights
      by <<- 0.0
      H <<- H; D <<- D
      params <<- c("Wz", "Wr", "Wh", "bz", "br", "bh", "Wy", "by")
      init_adam()  # Set up Adam optimizer's running averages
      callSuper(...)
    },
    init_adam = function() {
      # For each parameter, keep Adam optimizer book-keeping arrays
      m <<- setNames(lapply(params, function(p) { z <- field(p); z[] <- 0; z }), params)
      v <<- setNames(lapply(params, function(p) { z <- field(p); z[] <- 0; z }), params)
      t <<- 0
    },
    forward = function(x) {
      # "x" is a matrix: (window length, input features)
      Tn <- nrow(x)
      h <- rep(0.0, H)  # Start with empty hidden memory
      cache <- vector("list", Tn)  # We'll record what happens at each step for learning later
      for (tt in 1:Tn) {
        xt <- x[tt, ]                     # Input at time t
        hx <- c(h, xt)                    # Stick hidden and input together

        # "z" decides: how much old memory vs new info do we use?
        z <- sigmoid(as.numeric(Wz %*% hx) + bz)
        # "r" decides: how much of old memory to RESET to zero before new info
        r <- sigmoid(as.numeric(Wr %*% hx) + br)
        rhx <- c(r * h, xt)                # Old hidden memory, reset version
        # Propose new memory: "candidate"
        hc <- tanh(as.numeric(Wh %*% rhx) + bh)
        # Blend old and new: (1-z) * old + z * new
        h_new <- (1 - z) * h + z * hc
        # Save everything needed for backprop/training
        cache[[tt]] <- list(hprev = h, xt = xt, hx = hx, z = z, r = r, rhx = rhx, hc = hc, h_new = h_new)
        h <- h_new
      }
      # Final output neuron uses last hidden state (after all steps)
      output <- as.numeric(Wy %*% h + by)
      list(yhat = output, cache = cache, x = x)
    },
    backward = function(pack, dy) {
      # This method helps the model learn: "watched what happened, and if the output is off
      # by dy, how do we fix the weights?"
      cache <- pack$cache
      Tn <- length(cache)
      # Setup where to store all our "nudges" for each parameter
      g <- setNames(lapply(params, function(p) { z <- field(p); z[] <- 0; z }), params)
      # Start from end: last output influences the loss
      hT <- cache[[Tn]]$h_new  # Last hidden state
      g$Wy <- g$Wy + dy * matrix(hT, nrow = 1)
      g$by <- g$by + dy
      # "dh" is how much we wish to change h, start with last step's error
      dh <- as.numeric(base::t(Wy) * dy)
      # Go backwards through time (Backprop Through Time)
      for (tt in Tn:1) {
        ci <- cache[[tt]]
        # Calculate how to nudge each gate and parameter
        dz <- dh * (ci$hc - ci$hprev)
        dhc <- dh * ci$z
        dhprev <- dh * (1 - ci$z)
        da_h <- dhc * (1 - ci$hc^2)  # Derivative of tanh
        g$Wh <- g$Wh + outer(da_h, ci$rhx)
        g$bh <- g$bh + da_h
        drhx <- as.numeric(base::t(Wh) %*% da_h)
        d_rh <- drhx[1:H]
        dr <- d_rh * ci$hprev
        dhprev <- dhprev + d_rh * ci$r
        da_z <- dz * ci$z * (1 - ci$z)     # Derivative of sigmoid
        da_r <- dr * ci$r * (1 - ci$r)
        g$Wz <- g$Wz + outer(da_z, ci$hx)
        g$bz <- g$bz + da_z
        g$Wr <- g$Wr + outer(da_r, ci$hx)
        g$br <- g$br + da_r
        dhprev <- dhprev + (as.numeric(base::t(Wz) %*% da_z))[1:H] + (as.numeric(base::t(Wr) %*% da_r))[1:H]
        dh <- dhprev
      }
      # Prevent run-away gradients by clipping big updates
      for (p in params) g[[p]] <- pmin(pmax(g[[p]], -5), 5)
      g
    },
    # step() below plugs into the same shared Adam implementation used by ScratchLSTM
    # (mirrors the Python source's `step = ScratchLSTM.step` line)
    step = function(grads, lr = 0.01, b1 = 0.9, b2 = 0.999, eps = 1e-8) {
      adam_step(.self, grads, lr, b1, b2, eps)
    }
  )
)

# -- Tiny base-R toolkit: min-max scaler, windowing, training loop, metrics --

# Simple from-scratch min-max scaler that scales to [0,1] per feature (column-wise).
# Has inverse_transform for denormalizing outputs.
MinMax <- setRefClass(
  "MinMax",
  fields = list(mn = "numeric", rng = "numeric"),
  methods = list(
    fit = function(A) {
      A <- as.matrix(A); storage.mode(A) <- "double"
      mn <<- apply(A, 2, min)
      mx <- apply(A, 2, max)
      d <- mx - mn
      d[d == 0] <- 1.0   # Avoid division by zero if column is constant
      rng <<- d
      invisible(.self)
    },
    transform = function(A) {
      A <- as.matrix(A); storage.mode(A) <- "double"
      sweep(sweep(A, 2, mn, "-"), 2, rng, "/")
    },
    fit_transform = function(A) {
      fit(A)
      transform(A)
    },
    inverse_transform = function(A) {
      A <- as.matrix(A); storage.mode(A) <- "double"
      sweep(sweep(A, 2, rng, "*"), 2, mn, "+")
    }
  )
)

# Slices time series data into rolling windows suitable for supervised learning.
# - arr: input matrix of shape (T, num_features)
# - lookback: number of timesteps in the input window
# - target_col: column (1-indexed) to use as prediction target
# Returns: list(X = array(num_samples, lookback, num_features), y = vector of targets)
make_windows <- function(arr, lookback, target_col = 1) {
  arr <- as.matrix(arr)
  n <- nrow(arr) - lookback
  X <- array(0, dim = c(n, lookback, ncol(arr)))
  y <- numeric(n)
  for (i in 0:(n - 1)) {
    X[i + 1, , ] <- arr[(i + 1):(i + lookback), , drop = FALSE]
    y[i + 1] <- arr[i + lookback + 1, target_col]
  }
  list(X = X, y = y)
}

# Snapshot model parameters as a named list (for checkpointing best model)
snap_model <- function(m) setNames(lapply(m$params, function(p) m$field(p)), m$params)

# Restore parameter snapshot from a named list into the model
restore_model <- function(m, s) for (p in names(s)) m$field(p, s[[p]])

# Reshape one row of a 3D windows array back to a (timesteps, features) matrix
# (R silently drops size-1 dimensions when indexing, so we restore them explicitly).
extract_step <- function(X3, j) {
  xj <- X3[j, , ]
  if (is.null(dim(xj))) dim(xj) <- c(dim(X3)[2], dim(X3)[3])
  xj
}

# Training loop for time series models using per-sample stochastic gradient descent.
# - model: expects methods $forward, $backward, $step
# - Xtr, ytr: training data (windows, labels)
# - Xva, yva: validation data
# - epochs: max passes over train set
# - lr: learning rate (assumed used inside the model)
# - patience: epochs to wait for val loss improvement before early stopping
# Returns: list(hist = list(train=..., val=...), epochs_run = ...)
fit_model <- function(model, Xtr, ytr, Xva, yva, epochs = 40, lr = 0.01, patience = 8,
                       seed = 0, verbose = FALSE) {
  set.seed(seed)
  hist_ <- list(train = numeric(0), val = numeric(0))
  best <- Inf              # best validation loss seen so far
  best_snap <- NULL        # checkpoint (weights) with best val loss
  wait <- 0                # epochs since last improvement
  ntr <- dim(Xtr)[1]; nva <- dim(Xva)[1]
  ep_ran <- 0

  for (ep in 1:epochs) {
    tr <- 0.0
    # Shuffle train samples each epoch
    for (j in sample(ntr)) {
      xj <- extract_step(Xtr, j)
      res <- model$forward(xj)
      e <- res$yhat - ytr[j]
      tr <- tr + e * e
      # propagate error backward, call optimizer update (dL/dyhat = e for squared loss)
      model$step(model$backward(list(cache = res$cache, x = res$x), e))
    }
    # Compute validation MSE
    va <- mean(sapply(1:nva, function(j) (model$forward(extract_step(Xva, j))$yhat - yva[j])^2))
    tr <- tr / ntr
    hist_$train <- c(hist_$train, tr)
    hist_$val <- c(hist_$val, va)
    ep_ran <- ep
    # Early stopping: Check for improvement
    if (va < best - 1e-9) {
      best <- va
      best_snap <- snap_model(model)
      wait <- 0
    } else {
      wait <- wait + 1
      if (wait >= patience) break
    }
    if (verbose && (ep %% 5 == 0)) cat(sprintf("  epoch %3d  train %.4f  val %.4f\n", ep, tr, va))
  }
  # Restore best weights found
  if (!is.null(best_snap)) restore_model(model, best_snap)
  list(hist = hist_, epochs_run = ep_ran)
}

# Runs model$forward for each sample in X. Returns vector of predictions (length=dim(X)[1]).
predict_model <- function(model, X) {
  n <- dim(X)[1]
  sapply(1:n, function(j) model$forward(extract_step(X, j))$yhat)
}

# Evaluation metrics
rmse_ <- function(a, b) sqrt(mean((a - b)^2))

One-step vs multi-step forecasting

In previous evaluations, each prediction at time step t was generated using the true observed values from previous time steps as input—this approach is known as one-step (teacher forcing) forecasting. Here, the model always receives the actual past data, minimizing error accumulation.

However, in real-world forecasting, we often want to predict multiple steps into the future, and the true future observations are unavailable. Instead, we must use the model’s own predictions as input for subsequent steps. This approach is called multi-step (recursive) forecasting. At each time step, the model feeds its most recent forecast back into itself to predict the next value. While this enables forecasting entire sequences into the future, it can also lead to compounding errors, since mistakes at one step propagate forward.

Code 
# -- Recursive multi-step forecast over the whole test horizon --
# We want to predict all steps in the test set, but at each step, will only use the past window
# (of length LOOK) consisting of values already observed or recursively predicted. This mimics
# the real-world forecasting scenario, where future true values aren't available.

# 1. Start by initializing the 'window' to the last sequence seen before the test period.
window_ <- sim_s[(i_va - LOOK + 1):i_va, , drop = FALSE]  # last known window before forecast horizon

future <- c()  # This will collect all future predictions, step by step

# 2. For each step in the test horizon:
for (step in 1:(n - i_va)) {
  # a. Make a forecast for the next step using the current window
  nxt <- lstm$forward(window_)$yhat  # predict the next point (still scaled)
  # b. Save the forecasted value
  future <- c(future, nxt)
  # c. Update window: drop the oldest value, append the new prediction to the window
  window_ <- rbind(window_[-1, , drop = FALSE], matrix(nxt, ncol = 1))
}

# 3. Once all recursive predictions are complete, inverse-transform them to original scale
future <- as.numeric(y_scaler$inverse_transform(matrix(future, ncol = 1)))
# Actual future values for comparison
actual_f <- sim[(i_va + 1):n, 1]

# 4. Plotting for visualization
hist_range <- (i_va - 59):i_va
plot(hist_range, sim[hist_range, 1], type = "l", col = "gray50",
     xlim = c(i_va - 60, n), ylim = range(c(sim[hist_range, 1], actual_f, future)),
     xlab = "", ylab = "", main = "Multi-step (recursive) forecast")
lines((i_va + 1):n, actual_f, lwd = 2, col = "black")
lines((i_va + 1):n, future, lty = 2, lwd = 2, col = "tomato")
abline(v = i_va, lty = 3)
legend("topleft", legend = c("history", "actual future", "recursive forecast"),
       col = c("gray50", "black", "tomato"), lty = c(1, 1, 2), lwd = c(1, 2, 2), bty = "n")

15.6.1 The standard multivariate framing: series_to_supervised + min-max scaling

We follow the widely-used recipe for multivariate LSTM forecasting (Brownlee’s “time series to supervised learning” pattern), but the model is our from-scratch ScratchLSTM — no torch, Keras, or TensorFlow:

  • Scale all 8 columns to \([0,1]\) with our own MinMax scaler.
  • Reframe so the 8 features at time \(t\!-\!1\) (rice price + 7 factors) are the inputs \(X\), and the rice price at time \(t\) is the target \(y\). This is a one-lag, many-to-one setup with timesteps = 1.
  • Split by fixed row counts into train / val / test and a final 6-month forecast hold-out.
  • Train ScratchLSTM(8 → 32 → 1) with the harness from Part C, then report Training / Validation / Test / Forecast RMSE separately, un-scaling with the classic “concatenate the other columns back, invert, keep column 0” trick.
Code 
# -- Frame a time series as a supervised-learning table (lag features) --

# Convert a time series (or a sequence of multivariate observations) into a supervised
# learning data frame. This function creates lagged features for modeling: past observations
# as inputs (X) and future observations as outputs (y).
#
# Parameters:
#   data   : matrix of shape (n_samples, n_features). The original time series data.
#   n_in   : number of lag (input) time steps to include (e.g., n_in=1 creates features for t-1).
#   n_out  : number of future (output) time steps to predict (e.g., n_out=1 predicts t).
#   dropnan: whether to drop rows with any NA values (resulting from shifting operations).
#
# Returns: data frame where columns correspond to lagged inputs (t-n ... t-1) and forecast
# outputs (t ... t+n).
series_to_supervised <- function(data, n_in = 1, n_out = 1, dropnan = TRUE) {
  data <- as.matrix(data)
  n_vars <- ncol(data)
  n <- nrow(data)
  cols <- list()
  names_ <- c()

  # Create lagged input (X) sequences: for each lag i (from n_in to 1)
  for (i in n_in:1) {
    shifted <- rbind(matrix(NA, nrow = i, ncol = n_vars), data[1:(n - i), , drop = FALSE])
    cols[[length(cols) + 1]] <- shifted
    names_ <- c(names_, paste0("var", 1:n_vars, "(t-", i, ")"))
  }

  # Create output (y) sequences: current and future steps (from t to t+n_out-1)
  for (i in 0:(n_out - 1)) {
    shifted <- if (i == 0) data else rbind(data[(i + 1):n, , drop = FALSE], matrix(NA, nrow = i, ncol = n_vars))
    cols[[length(cols) + 1]] <- shifted
    label <- if (i == 0) paste0("var", 1:n_vars, "(t)") else paste0("var", 1:n_vars, "(t+", i, ")")
    names_ <- c(names_, label)
  }

  # Combine all columns and assign names
  agg <- do.call(cbind, cols)
  colnames(agg) <- names_
  agg <- as.data.frame(agg)

  # Optionally drop rows with any NA values (from shifting)
  if (dropnan) agg <- agg[stats::complete.cases(agg), ]
  agg
}

Evaluating each split — the inverse-scaling trick

Predictions come out on the \([0,1]\) scale. To read them in USD/tonne we glue each prediction back next to the other 7 (t-1) columns, run scaler$inverse_transform, and keep column 1 (rice price). Because min-max scaling inverts each column independently, the filler columns don’t affect the recovered price — they only make the array the right shape.

Code 
# -- One helper reproduces Training / Validation / Test / Forecast RMSE --
rmse_report <- function(X3, y, name) {
  yhat <- predict_model(model_d, X3)                             # scaled prediction
  X2 <- matrix(X3, nrow = dim(X3)[1], ncol = dim(X3)[3])          # (samples, features)
  inv_yhat <- scaler$inverse_transform(cbind(yhat, X2[, -1, drop = FALSE]))[, 1]
  inv_y    <- scaler$inverse_transform(cbind(y,    X2[, -1, drop = FALSE]))[, 1]
  cat(sprintf("%s RMSE: %.3f\n", name, rmse_(inv_y, inv_yhat)))
  list(inv_y = inv_y, inv_yhat = inv_yhat)
}

What Part D teaches

  • We report Training, Validation, Test and Forecast RMSE separately, so over-fitting and regime shift are both visible.
